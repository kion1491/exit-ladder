# 매도 사다리 — 분할익절 역산 계산기

매수가·손절가·원하는 손익비·분할 수를 넣으면, **그 손익비를 만족하는 분할 매도가격 사다리를 역산해서** 보여주는 웹 계산기입니다.

기존 도구들이 "목표가를 넣으면 손익비를 알려주는" 방향이라면, 이 도구는 그것을 뒤집었습니다. **손익비가 입력이고 목표가가 출력**입니다. "이 거래가 성립하려면 주가가 어디까지 가야 하는데, 그게 말이 되나?"를 사람이 판정하게 만드는 것이 목적입니다. 기계는 산수를 하고, **도달 가능성 판단은 사람이 합니다.**

## 화면 구성

- **최종 매도가 히어로** — 판단할 단 하나의 숫자를 크게. "현실적입니까? 아니라면 이 거래는 하지 않는다."
- **매도 계획 표** — 차수·매도가·비중(·주수). 실제 주문에 그대로 옮겨 적는 표
- **판정 칩** — 손절폭 / 본전 승률 / 필요 상승률
- **수직 가격 레일** — 손절가(파랑)부터 매도가(빨강)까지 실제 가격 간격 그대로. 현실 상한가를 넣으면 주황 점선과 이내/초과 배지
- **탭** — 저장해 둔 계획들이 로그인하면 탭으로 열립니다. 같은 탭에서 고쳐 저장하면 그 계획이 갱신되고, 탭을 닫으면 계획이 지워집니다(확인 후, 실행 취소 가능)

계산 버튼은 없습니다. 입력이 바뀌는 즉시 다시 계산합니다. 라이트/다크 테마와 모바일·데스크톱 반응형을 지원합니다.

## 계산 규칙

`R = 매수가 − 손절가`(1주당 리스크), `k = 손익비`일 때:

| 분할 수 | 매도가 | 비중 |
|---|---|---|
| 1분할 | E + kR | 100% |
| 2분할 | E + R, E + (2k−1)R | 50% / 50% |
| 3분할 | E + R, E + kR, E + (2k−1)R | 33% / 33% / 34% |

- 1차 매도가를 **+1R에 고정**: 체결되면 손절을 본전으로 올려 그 뒤로는 잃지 않는 거래가 된다
- 비중 가중평균 매도가는 정확히 `E + kR` (호가 내림 전 기준)
- **매도가는 항상 호가단위 내림** (보수적). 국내 가격대별 7구간, 미국 센트 단위
- 수수료(왕복 0.3%)는 매도가에 섞지 않고 순손익 표시에만 반영

## 기술 스택

Next.js(App Router) · TypeScript · Tailwind CSS · shadcn/ui · vitest · Vercel 배포

데이터는 구글시트에 저장하고, 시트 접근은 Apps Script 웹앱(`apps-script.gs`)이 담당합니다.
브라우저는 이 앱의 서버(`/api/plans`)만 부르고, **Apps Script 주소와 키는 서버 환경변수에만 있어 브라우저로 내려가지 않습니다.** 개발자도구를 열어도 키는 보이지 않습니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # 계산 검증 벡터 (기획 검증 벡터 10종 + 경계·엣지)
npm run lint     # 커밋 전 필수 (CI에서도 강제됨)
npm run build    # 정적 산출물 out/ 생성
```

### 커스터마이징된 shadcn 컴포넌트

`components/ui/`의 **input.tsx · toggle.tsx · button.tsx**는 테두리를 `border-border-strong`
토큰으로 직접 수정했습니다(WCAG 비텍스트 대비 3:1). `shadcn add --overwrite`로 다시 받으면
이 수정이 사라지니, 파일 상단의 CUSTOMIZED 주석을 확인하고 재적용하세요.

로컬에서 저장 기능까지 쓰려면 `.env.local`에 아래 값이 필요합니다(커밋되지 않습니다).

```
GAS_URL=https://script.google.com/macros/s/.../exec
GAS_KEY=Apps Script의 KEY와 같은 값
APP_USERNAME=로그인 아이디
APP_PASSWORD=로그인 비밀번호
SESSION_SECRET=아무 긴 무작위 문자열
```

## 배포

### 1. Apps Script (저장 백엔드)

저장 기능을 쓰지 않을 거라면 건너뛰어도 계산기는 완전히 동작합니다.

1. 구글 드라이브에서 **새 스프레드시트** 생성
2. **확장 프로그램 → Apps Script** 열기
3. 기본 코드를 지우고 `apps-script.gs` 내용을 통째로 붙여넣기
4. 맨 위 `KEY`를 **본인만의 문자열로 변경** (비밀번호 역할)
5. **배포 → 새 배포 → 웹 앱** — 실행: **나** / 액세스: **링크가 있는 모든 사용자**
6. 웹앱 URL(`.../exec`) 복사

기록용 "매도사다리" 시트는 첫 저장 때 자동 생성됩니다.

> ⚠️ **코드를 고친 뒤에는** 저장만으로 반영되지 않습니다. **배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 해야 실제 웹앱에 적용됩니다.

### 2. Vercel (앱)

1. [vercel.com](https://vercel.com)에 GitHub 계정으로 로그인 → 이 저장소를 Import
2. **Environment Variables**에 5개(`GAS_URL`, `GAS_KEY`, `APP_USERNAME`, `APP_PASSWORD`, `SESSION_SECRET`)를 등록
3. Deploy

이후 `main`에 푸시하면 자동 배포됩니다. 환경변수를 바꾼 뒤에는 재배포해야 반영됩니다.

### 3. 사용

발급된 주소에서 **아이디·비밀번호로 로그인**하면 바로 쓸 수 있습니다. 웹앱 주소와 키는 서버에 있으므로 기기마다 설정을 넣을 필요가 없습니다. 로그인은 30일간 유지됩니다.

## 저장 데이터

시트 컬럼: `날짜 | 종목명 | 시장 | 매수가 | 손절가 | 분할수 | 손익비 | 매도가 | 예산 | 상한가 | 메모 | ID | 수정일시`

계획 하나가 시트 한 줄입니다. `ID`로 같은 계획임을 알아보므로 종목명을 바꿔도 갱신이 이어집니다.

> 예전 형식(ID 칸이 없는) 시트는 새 코드가 처음 뜰 때 한 번 정리됩니다 — 원본을 `매도사다리_백업_날짜` 시트로 복사해 둔 뒤, 같은 종목명이 여러 줄이면 가장 최근 것만 남기고 각 줄에 ID를 붙입니다.

## 이 도구가 하지 않는 것

계획→진입→종료 상태 추적 · 실시간 시세 · 자동 주문 · 분할매수 계산(전량 일괄 매수 전제) · 로그인/다중 사용자

## 사용 규칙

> **1차 매도가(+1R) 체결 시 손절을 본전으로. 손절 이동은 위로만. 최종가가 비현실적이면 이 거래는 하지 않는다.**

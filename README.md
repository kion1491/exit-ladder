# 매도 사다리 — 분할익절 역산 계산기

매수가·손절가·원하는 손익비·분할 수를 넣으면, **그 손익비를 만족하는 분할 매도가격 사다리를 역산해서** 보여주는 모바일 웹 계산기입니다.

기존 도구들이 "목표가를 넣으면 손익비를 알려주는" 방향이라면, 이 도구는 그것을 뒤집었습니다. **손익비가 입력이고 목표가가 출력**입니다. 역DCF처럼 "이 거래가 성립하려면 주가가 어디까지 가야 하는데, 그게 말이 되나?"를 사람이 판정하게 만드는 것이 목적입니다.

기계는 산수를 하고, **도달 가능성 판단은 사람이 합니다.**

---

## 화면 구성

- **입력** — 종목명(선택) · 시장(국내/미국) · 매수가 · 손절가 · 분할 수(1/2/3) · 손익비(슬라이더 + 직접입력) · 예산(선택) · 현실 상한가(선택) · 메모(선택)
- **판정 칩** — 손절폭 / 본전 승률 / 필요 상승률
- **수직 가격 레일** — 손절가(파랑)부터 매도가들(빨강)까지 실제 가격 간격 그대로 세로로 배치. 현실 상한가를 넣으면 주황 점선이 그어지고, 그 선을 넘는 매도가에 "초과" 배지가 붙습니다
- **예산 블록** — 예산을 넣으면 주수·매수금액·손절 시 순손익·전량 익절 시 순손익 (국내 시장 전용)
- **저장** — 구글시트에 계획 스냅샷을 한 줄씩 적재하고, 저장 목록을 카드로 조회

계산 버튼은 없습니다. 입력이 바뀌는 즉시 다시 계산합니다.

---

## 계산 규칙

`R = 매수가 − 손절가`(1주당 리스크), `k = 손익비`일 때:

| 분할 수 | 매도가 | 비중 |
|---|---|---|
| 1분할 | E + kR | 100% |
| 2분할 | E + R, E + (2k−1)R | 50% / 50% |
| 3분할 | E + R, E + kR, E + (2k−1)R | 33% / 33% / 34% |

- 1차 매도가를 **+1R에 고정**하는 이유: 여기가 체결되면 손절을 본전으로 올려서, 그 뒤로는 잃지 않는 거래가 되기 때문입니다
- 비중 가중평균 매도가는 정확히 `E + kR`이 됩니다(호가 내림 전 기준)
- **매도가는 항상 호가단위로 내림**합니다(보수적). 국내는 가격대별 7구간 호가표, 미국은 센트 단위
- 매도가에는 수수료를 섞지 않습니다. 왕복 거래비용 0.3%는 순손익 표시에만 반영합니다

## 배포 절차

### 1. Apps Script (저장 백엔드)

저장 기능을 쓰지 않을 거라면 이 단계를 건너뛰어도 계산기는 완전히 동작합니다.

1. 구글 드라이브에서 **새 스프레드시트**를 만듭니다
2. 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다
3. 기본으로 있는 코드를 지우고 이 저장소의 `apps-script.gs` 내용을 통째로 붙여넣습니다
4. 맨 위의 `var KEY = 'CHANGE_ME_여기를_본인만의_문자열로_바꾸세요';` 에서 **KEY를 본인만의 문자열로 바꿉니다**
   - 이 값이 비밀번호 역할을 합니다. 웹앱 주소를 아는 사람이라도 이 키를 모르면 저장·조회를 할 수 없습니다
5. **배포 → 새 배포 → 유형 "웹 앱"** 을 선택하고 아래처럼 설정합니다
   - 실행: **나**
   - 액세스 권한이 있는 사용자: **링크가 있는 모든 사용자**
6. 배포하면 나오는 **웹앱 URL**(`.../exec`로 끝나는 주소)을 복사해 둡니다

> 기록이 쌓일 "매도사다리" 시트는 첫 저장 때 스크립트가 알아서 만듭니다. 미리 준비할 필요 없습니다.

### 2. GitHub Pages (프론트)

1. 이 저장소를 GitHub에 푸시합니다
2. 저장소의 **Settings → Pages**로 갑니다
3. Source를 배포할 브랜치(`main` 등)와 루트(`/`)로 지정하고 저장합니다
4. 잠시 뒤 발급되는 주소로 접속하면 계산기가 뜹니다

`index.html` 한 파일이 전부라서 빌드 과정이 없습니다. 파일을 그대로 올리기만 하면 됩니다.

### 3. 연결

1. 배포된 사이트를 열고 맨 아래 **저장 → "저장 설정 (웹앱 주소 · 키)"** 을 펼칩니다
2. 1단계에서 복사한 **웹앱 URL**과 직접 정한 **KEY**를 넣습니다
3. 이 값은 브라우저에 기억되므로 다음 방문 때 다시 넣지 않아도 됩니다

> 기기나 브라우저를 바꾸면 다시 넣어야 합니다. 시크릿 모드처럼 저장이 막힌 환경에서도 계산기 자체는 정상 동작합니다.

### ⚠️ 코드를 고친 뒤에는

**Apps Script는 코드를 수정하는 것만으로 반영되지 않습니다.** 반드시 **배포 → 배포 관리 → (연필 아이콘) → 버전 "새 버전" → 배포**를 눌러야 실제 웹앱에 적용됩니다. 이걸 빠뜨리면 예전 코드가 계속 돌아가면서 "왜 안 고쳐지지?" 하게 됩니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 계산기 전체 (CSS·JS 인라인, 단일 파일) |
| `apps-script.gs` | 구글시트 저장 백엔드 |
| `README.md` | 이 문서 |

빌드 도구와 프레임워크를 쓰지 않습니다. 외부에서 가져오는 것은 구글 폰트 하나뿐이고, 그마저 실패해도 시스템 폰트로 대체되어 정상 동작합니다.

---

## 저장 데이터 형식

시트 컬럼 순서:

```
날짜 | 종목명 | 시장 | 매수가 | 손절가 | 분할수 | 손익비 | 매도가 | 예산 | 상한가 | 메모
```

저장된 데이터의 **수정·삭제 화면은 없습니다.** 필요하면 구글시트에서 직접 하면 됩니다.

---

## 이 도구가 하지 않는 것

- 계획 → 진입 → 종료 상태 추적 (매매일지의 영역)
- 실시간 시세 조회, 자동 주문, 증권사 연동
- 분할매수 계산 (전량 일괄 매수를 전제로 합니다)
- 로그인·다중 사용자

---

## 사용 규칙

> **1차 매도가(+1R) 체결 시 손절을 본전으로. 손절 이동은 위로만. 최종가가 비현실적이면 이 거래는 하지 않는다.**

이 도구는 진입·청산 계산기이지 매매 전체를 지휘하는 시스템이 아닙니다. 출력된 최종 매도가가 차트와 펀더멘털에 비추어 현실적인지 판단하는 것은 사람의 몫입니다.
